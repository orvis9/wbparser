🛒 Парсер Wildberries с историей цен
Скрипт для автоматического сбора всех товаров продавца на Wildberries с сохранением истории изменения цен. Поддерживает как числовые, так и строковые ID продавцов (например, positronica), обходит ограничение в 10 000 товаров через ценовые фильтры.

📌 Возможности
✅ Сбор всех товаров продавца (обход лимита 10 000 через ценовые диапазоны)

✅ Извлечение ID, названия, бренда и актуальной цены

✅ Поддержка строковых ID продавцов (например, itstore, yandex-factory)

✅ Сохранение истории цен в Excel (отдельный лист для каждого продавца)

✅ Оптимизированная запись в Excel через векторизованные операции pandas (обработка 50 000+ записей за секунды)

✅ Детальное логирование времени выполнения каждого этапа

✅ Удаление старых карточек в браузере для поддержания высокой скорости

✅ Дедупликация товаров по артикулу

✅ Автоматическое восстановление при повреждении файла истории

⚙️ Требования
Python 3.9 или новее

Установленные библиотеки (см. requirements.txt)

Браузер Chromium (устанавливается автоматически через playwright)

📦 Установка
bash
# Клонируйте репозиторий
git clone https://github.com/your-username/wb-parser.git

pip install -r requirements.txt

patchright install chromium
🧩 Настройка
1. Файл со списком продавцов (sellers.xlsx)
Создайте в корневой папке файл sellers.xlsx. Скрипт читает первые две колонки и столбец «Разбивка» (остальные, например название или количество, игнорируются):

seller_id	active	разбивка
4072488	1	1
positronica	1	0
1234567	0	1
seller_id – ID продавца (число или строка)

active – 1 (парсить) или 0 (пропустить)

разбивка – 1 (парсить по ценовым диапазонам; для больших каталогов) или 0 (парсить одним запросом без разбивки; для небольших каталогов). Если столбец отсутствует или значение пустое – по умолчанию 1.

Строка заголовка не обязательна: если она есть, она будет пропущена автоматически.

Если файл не найден, скрипт создаст его автоматически с примером.

2. Конфигурация в скрипте
В начале файла wb_parser.py вы можете изменить:

python
SELLERS_FILE = "sellers.xlsx"       # файл со списком продавцов
PRICE_HISTORY_FILE = "par.xlsx"     # файл для истории цен
KEEP_CARDS = 700                    # количество оставляемых карточек на странице
MAX_STALL = 5                       # число итераций без новых товаров для остановки
HEADLESS = False                    # True – браузер без интерфейса
Также вы можете настроить ценовые диапазоны в переменной PRICE_RANGES для обхода ограничения 10 000 товаров (цены в копейках).

🚀 Использование
bash
python wb_parser.py
После запуска:

Откроется окно браузера (если HEADLESS = False).

Скрипт последовательно парсит каждого активного продавца по всем ценовым диапазонам.

Собранные товары сохраняются в par.xlsx на отдельный лист с именем продавца.

В папке появится лог-файл timing_log_YYYYMMDD_HHMMSS.txt с детальными таймингами.

📊 Формат Excel-файла (par.xlsx)
Каждый продавец получает отдельный лист с именем seller_id.

Структура листа:

id	name	brand	seller_id	2026-08-19 15:27:57	2026-08-20 10:00:00	...
1210960506	Наушники Дропс с Алисой	Яндекс	4072488	7264	6999	...
...	...	...	...	...	...	...
id – артикул товара (строка)

name – название

brand – бренд

seller_id – ID продавца

Остальные столбцы – дата и время запуска, значения – цена товара на тот момент (0, если товар отсутствовал в продаже)

🧠 Принцип работы
Загрузка страницы продавца через Playwright (с маскировкой через patchright).

Бесконечная прокрутка с удалением старых карточек (чтобы DOM оставался лёгким).

Сбор данных только с новых карточек по индексам (инкрементальный подход).

Ценовые фильтры – если товаров > 10 000, скрипт проходит по всем ценовым диапазонам и объединяет результаты с дедупликацией.

Сохранение в Excel с векторизованными операциями (быстро даже для 50 000+ записей).

Логирование каждого этапа для диагностики производительности.
